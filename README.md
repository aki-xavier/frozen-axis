# frozen-axis

## Frozen Memory and Open Inversion: A Conditional Risk-Gap Bound <!-- markdownlint-disable-line MD013 -->

Original Chinese title: 冻结记忆与开放反演：一个条件风险差界

The project name frozen-axis comes from the paper's core concept: one side of
the decision axis holds values frozen into the training corpus and fixed at
inference time (Mode B), while the other side holds values given on the spot
by current evidence or by analytic invariants (Mode A); the paper's conditional
result concerns whether frozen values can satisfy its non-freezability and
bounded-description hypotheses on the open set.

📄 **Paper: [paper-slim.pdf](dist/paper-slim.pdf) (24 pages). LaTeX source in
the official JMLR jmlr2e style, rebuild with `./scripts/build.sh`**

This repository contains a theoretical paper (English, LaTeX source) together
with its Lean 4 machine-verification artifact. Under explicit and separately
checkable assumptions, the paper proves a conditional class-exclusion: a
specified class of offline-frozen rules satisfying uniform bounded description
and scale-restricted realization cannot be complete on its own for open
inversion tasks. Open inversion tasks are delimited by four
criteria: observations are ill-posed, the required context strength is
heterogeneous and content-addressed by the evidence, inference inputs are not
constrained by the training distribution, and the demand rule cannot be given
within any pre-given tolerance on the open set by any values frozen before
inference begins. The last criterion is class-relative: a demand barrier holds
at every scale, while realization is required at one class-admissible scale
rather than at every scale. Together with a uniform bounded-description rate
and a fixed evidence-instantiated benchmark, these hypotheses imply a positive
floor on the risk gap, so P4 is a sufficient condition for a bound rather than a
restatement of the negation. The argument unfolds along a decision axis: values
given on the spot by current evidence or analytic invariants belong to Mode A,
while values given offline from training-corpus statistics or manual setting
and frozen at inference time belong to Mode B. Mode B provenance alone does not
prove failure; the conditional theorem excludes a specified bounded-description
class under P4 and a positive gap, and composite systems containing Mode A are
not ruled out. The algebra and a toy closure are machine-verified with Lean 4 +
Mathlib, with zero `sorry` and zero warnings.

## Building

Paper (a local TeX distribution is required: TeX Live, MacTeX or TinyTeX with
`latexmk`, `pdflatex` and `bibtex` — JMLR production also compiles with
latexmk via pdflatex):

```bash
./scripts/build.sh          # build paper/paper-slim.tex
./scripts/build.sh slim     # same target
```

Intermediate output is written to `build/slim/`. A clean build is copied to
`dist/paper-slim.pdf`; a build with LaTeX errors leaves the published PDF
untouched.

The driver is `latexmk`, which re-runs `pdflatex` and `bibtex` until the
cross-references and the bibliography settle; the compile flags live in
[`paper/latexmkrc`](paper/latexmkrc). Set `USE_LATEXMK=0` to fall back to an
explicit `pdflatex` ×3 + `bibtex` sequence, which is also what a machine
without `latexmk` gets.

A minimal TeX installation needs one extra package. `jmlr2e.sty` typesets the
`©` of the first-page copyright footnote and the itemize bullets in TS1, and
TinyTeX carries the EC/TC Computer Modern fonts only as METAFONT sources, so
`pdflatex` would have to render a bitmap for every size used:

```bash
tlmgr install cm-super   # Type 1 EC/TC fonts, identical metrics, no bitmaps
```

`scripts/build.sh` names that command when a missing font is what stopped a
build. The bibliography is processed by BibTeX rather than biber, because
`jmlr2e.sty` loads `natbib` and the paper uses `\bibliographystyle{plainnat}`,
a BibTeX style; biber only works with `biblatex`, which this style does not
use.

Builds are byte-reproducible. pdfTeX would otherwise stamp the wall-clock time
into the PDF and derive the trailer `/ID` from it, so two builds of identical
sources would differ byte-wise; `scripts/build.sh` pins `SOURCE_DATE_EPOCH`
for the embedded dates and `paper/paper-slim.tex` seeds the trailer id through
`\pdftrailerid`. Rebuilding unchanged sources therefore reproduces
`dist/paper-slim.pdf` exactly, and `git status` is a reliable signal that the
committed PDF matches the source. Export `SOURCE_DATE_EPOCH` to override the
pinned date.

Lean artifact (the toolchain version is pinned in `lean-proof/lean-toolchain`,
currently `leanprover/lean4:v4.34.0`):

```bash
cd lean-proof && lake build
```

Package the Lean artifact:

```bash
./package-lean-proof.sh   # writes lean-proof.zip by default
```

## Paper-to-Lean correspondence

Section 6 of the paper reports the three levels of verification strength, and
Table 2 gives the per-component stratification from the toy carrier to the
continuous case (Tier A, the carrier-independent algebraic core; Tier B,
structured general forms; Tier C, the remaining analytic and modeling
components). Section 4 gives the operational procedure for deciding the mode
of an implementation. Tier C holds the continuous-side
Euler--Lagrange correspondence, general network output variation, the zero-safe
table equivalence in general form, BD, P4a/P4b, and Barrier-to-Gap. The core
correspondences:
